# TP-LINK 商用云平台开放接口文档（文本版）

**权威版本：2026-08-31**（`doc/TP-LINK商用云平台开放接口文档-2026-08-31.pdf`）。后续 TP-LINK 商云相关开发以此版本为准。

本目录是该 PDF 的逐章文本抽取，方便 grep / 按行读取，替代直接读 PDF。

## 使用方法

1. 在 [INDEX.md](INDEX.md) 中 grep 接口 Path（如 `setEnableByAlarmType`）或中文标题（如 `人形`）。
2. 按"位置"列的 `文件:行号`，用 Read 的 `offset` 打开该节阅读。
3. 需要跨章节全文检索时，直接 grep 本目录下的 `*.md`。

| 文件 | 内容 |
|---|---|
| `1.1-1.3-概述-鉴权-签名.md` | 术语、开发前准备、**请求签名算法**、接口规则、字段类型 |
| `1.4.01` ~ `1.4.22` | 各 API 章节（一章一个文件） |
| `1.5-错误码.md` | 全部错误码 |
| `CHANGELOG.md` | 文档变更记录：历次版本之间文档本身的差异（最新在上） |
| `changelog_infect.md` | 版本影响记录：每个版本对本工程代码的影响，包括兼容性、可利用的新能力、代码问题跟踪（最新在上） |
| `_tools/` | 更新流水线脚本：`update.sh`、`pdf2md.pl`、`compare_sections.pl`、`compare_endpoints.pl` |

## 抽取格式说明（阅读前必读）

- 每节正文放在 `text` 代码块里，是 `pdftotext -layout` 的原始列排版。PDF 里的**参数表是多列嵌套表格**：左列是参数名和类型，右列是说明，嵌套对象的子字段缩进在中间列。表格跨页时，同一行的内容可能被拆开、错开几行，读的时候要按列对齐理解。
- 原文的流程图只保留了图里的文字（比如 1.4.7.1 的报警开关流程），截图没有保留。有疑问时回到 PDF 对应页核对，页码见 PDF 目录。
- PDF 自身有编号错误：1.4.18 云停车章节正文里的小节号和目录不一致，比如正文写 1.4.18.8，目录写 1.4.18.4。本目录统一**按目录编号**。
- 章节之间的交叉引用（比如"详见 1.4.7.2"）用的是 PDF 原编号，可以直接在 INDEX.md 里查。

## 新版文档到来时

1. 把新 PDF 放到 `doc/`，文件名带日期：`TP-LINK商用云平台开放接口文档-YYYY-MM-DD.pdf`。
2. 在 Git Bash 中运行（旧版会自动选 `doc/` 下日期早于新版的最近一版）：
   ```bash
   doc/tplink-api/_tools/update.sh "doc/TP-LINK商用云平台开放接口文档-YYYY-MM-DD.pdf"
   ```
   脚本会做这几件事：
   - 用新版重新生成本目录的章节文件（`1.*.md`）和 `INDEX.md`，README、两份 changelog 等手写文件不动；
   - 打印摘要：增删的 Path、增删的错误码、项目在用接口是否还在；
   - 在临时目录留下 `sections.txt`（逐节差异）和 `endpoints.txt`（在用接口字段级差异）。
   - 如果输出里出现 `MISSING`，说明有小节标题没定位到，需要先修 `pdf2md.pl`。
3. 阅读报告，逐条到新旧文本中确认真实改动。报告里有不少排版噪音，例如仅页码变化，或 `#N` 同名小节错位配对，这些需要剔除。
4. 在 `CHANGELOG.md` **顶部**新增一节，只写文档本身改了什么，不写对本工程的影响。然后更新它顶部的版本表，把新版标为当前权威版本。
5. 在 `changelog_infect.md` **顶部**新增同名一节，写对本工程的影响：
   - 在用接口是否兼容，不兼容时列出需要修改的代码位置；
   - 有哪些可利用的新能力；
   - 代码问题跟踪，包括更新已记录问题的状态。

只想对比、不覆盖文档时（比如补做历史版本），加 `--compare-only`，并显式给出旧版：
`update.sh <新版PDF> <旧版PDF> --compare-only`

**为什么不直接 diff 文本**：PDF 表格跨页时会换行、错位，直接 diff 几乎每节都会报差异。脚本的做法有两种，都与排版顺序无关，能过滤掉这类噪音：
- 比较两版的接口 Path 集合；
- 按小节比较"英文标识符集合 + 中文字符多重集"。
