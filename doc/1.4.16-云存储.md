##### 1.4.16.1.1 metaMap

```text
事件的元数据信息，其中的元数据由设备上传录像时携带。

目前支持的元数据如下：

字段名                 类型      说明

needCover           string  是否需要进行隐私遮蔽。如果设备上传录
                            像时携带存在，则取值为”true”或者”false”。
                            如果不存在，则表示不需要进行隐私遮蔽。

rotate              string  需要进行旋转的角度，如果设备上传录像
                            时未携带对应的元数据，则该字段不存在，
                            无需进行旋转。如果设备上传录像时携带

                            了对应的元数据，则值为对应元数据的值。

mjpegDataUnit       string  是否为特定的 MJPEG 编码的数据，如果设
                            备上传录像时未携带对应的元数据，则该
                            字段不存在。如果设备上传录像时携带了

                            对应的元数据，则值为对应元数据的值。

isConsecutive       string  是否为连续云录像，如果设备上传录像时
                            未携带对应的元数据，则该字段不存在。
                            如果设备上传录像时携带了对应的元数

                            据，则值为对应元数据的值。

deviceModuleSpec string     设备能力集，如果设备上传录像时未携带
                            对应的元数据，则该字段不存在。如果设
                            备上传录像时携带了对应的元数据，则值

                            为对应元数据的值。

channelIdList       string  该设备需要进行录像同步的通道号，如果
                            设备上传录像时未携带对应的元数据，则

                            该字段不存在。如果设备上传录像时携带
                            了对应的元数据，则值为对应元数据的值。

maxDuration         string  该段云录像的最大录像时长，如果设备上
                            传录像时未携带对应的元数据，则该字段

                            不存在。如果设备上传录像时携带了对应
                            的元数据，则值为对应元数据的值。

timeZone            string  设备上传录像时的时区，如果设备上传录
                            像时未携带对应的元数据，则该字段不存

                            在。如果设备上传录像时携带了对应的元

                            数据，则值为对应元数据的值。

示例:

    {
       "needCover": "true",
       "rotate": "90",
       "mjpegDataUnit ": "true",
       "isConsecutive": "true",

        "deviceModuleSpec": "express;doorbellLog",
        "channelIdList": "0,1",
        "maxDuration": "60",
        "timeZone": "GMT+08:00"
      }
```

      snapshotBucket    封面图存储桶
      string

      snapshotName      封面图名称

功能说明
      通过起止时间，分页获取此间的所有事件的列表。

      1. 若startTimestamp和endTimestamp均为-1，则表示从最新的事件开始获取，查
           询结果为倒序。

      2. 若startTimestamp为-1，endTimestamp为正，则表示从endTimestamp的时间开
           始往后获取，查询结果为正序，查询到的第一个为起始时间大于endTimestamp
           的事件。

      3. 若endTimestamp为-1，startTimestamp为正，则表示从startTimestamp的时间开
           始往前获取，查询结果为倒序，查询到的第一个为起始时间小于等于
           startTimestamp的事件。

      4. 若startTimestamp和endTimestamp均为正，且startTimestamp>endTimestamp，
           获取起始时间落在 (end Timestamp, startTimestamp] 的事件，查询结果为倒
           序。

      5. 若startTimestamp和endTimestamp均为正，且startTimestamp<endTimestamp，
           获取起始时间落在 [startTimestamp, endTimestamp) 的事件，查询结果为正
           序。

      6. 若startTimestamp和endTimestamp均为正，且startTimestamp=endTimestamp，
           则查询是否存在起始时间为startTimestamp的事件。

}

"xxx", "timestamp": "1784879920000"}
         ]
      }
