### 1.2.2 请求签名

#### 1.2.2.1 为什么要进行签名

```text
      签名通过以下方式帮助保护请求：
      1. 验证请求者的身份

           签名确保请求是由持有有效访问密钥的人发送的。AK/SK 获取方式参见上一节的描述。
      2. 保护传输中的数据

           为了防止请求在传输过程中被篡改，TP-LINK 商用云平台开放接口会使用请求参数来计算
           请求的哈希值，并将生成的哈希值加密后作为请求的一部分，发送到商云服务器。服务器
           会使用收到的请求参数以同样的过程计算哈希值，并验证请求中的哈希值。如果请求被篡
           改，将导致哈希值不一致，商云开放接口将拒绝本次请求。
```

      // 此处填写您的 ak

      public static byte[] hmac256(byte[] key, String msg) throws Exception {
            Mac mac = Mac.getInstance("HmacSHA256");
            SecretKeySpec secretKeySpec = new SecretKeySpec(key, mac.getAlgorithm());
            mac.init(secretKeySpec);
            return mac.doFinal(msg.getBytes(UTF8));

      }

      public static String sha256Hex(String s) throws Exception {
            MessageDigest md = MessageDigest.getInstance("SHA-256");
            byte[] d = md.digest(s.getBytes(UTF8));
            return DatatypeConverter.printHexBinary(d).toLowerCase();

      }

#### 1.2.2.5 临时 AK/SK

```text
      因客户端也可能存在直接访问商云开放接口的情况，直接将应用的 AK/SK 写在客户端程序中并
不是一种可靠的方式。因此我们提供了获取临时 AK/SK 的接口，可以通过用户的后台服务器凭长期
AK/SK 计算签名来调用该接口来获取临时 AK/SK 并下发到客户端，如有进一步的安全性需求，可
以在下发过程中对临时 AK/SK 进行加密传输。获取到的临时 AK/SK 与长期 AK/SK 在权限和使用方
式上都是一致的，但可以由用户自定义有效期。该接口定义详见 1.4.1.1 节。
```
