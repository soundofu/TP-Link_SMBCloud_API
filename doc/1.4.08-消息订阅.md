#### 1.4.8.6 推送消息体签名

```text
      如果用户使用 1.4.8.3 设置签名密钥，则向订阅地址推送消息体时会在请求头中带上签名，签名
在请求头中的字段名是 Signature。

      请求头签名计算流程：
      1、通过 Jackson 库的 ObjectMapper 类将消息体对象转换为 json 字符串（对象为 null 的字段保留，
字段之间、键值之间不存在空格），消息体转换的 json 字符串示例：
{"mac":"00-FF-00-17-00-18","deviceName":"TL-NIPC5464P-A6
2.0","parentQrCode":null,"parentMac":null,"channelId":1,"msgId":"55045081c4cd494a870ecef902f8e936"
,"imageId":"5453610","time":"1726817278","msgType":"monitorAlarm","msgContentType":["movement
Detected"],"qrcode":"16E0091709B04C926","qrCode":"16E0091709B04C926"}
      2、以 1.4.8.3 中设置的密钥和请求体转换的 json 字符串为参数，使用 HmacSHA256 进行加密计
算后，转换为 16 进制字符串作为签名，放入请求头的 Signature 字段中。
      3、用户订阅地址接收到推送消息后，若需要签名认证，可按照第 2 点的方式计算签名，和放入
请求头的 Signature 字段值比较。
      以 SpringBoot 编写的接收地址为例，假设如下接口/receiveAlarmMsg 的消息订阅地址，接收到
的请求参数 requestBodyStr 是推送消息体转为 json 的形式（对象为 null 的字段保留，字段之间、键
值之间不存在空格；若计算签名不匹配请仔细检查参与计算的请求体），如果需要校验推送消息签名，
校验逻辑可参考示例：

import com.fasterxml.jackson.databind.ObjectMapper;
import java.nio.charset.StandardCharsets;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import javax.xml.bind.DatatypeConverter;

@Slf4j
@RestController
public class MsgReceiveDemo {

      // 用户设置的 sk
      private final static String sk = "51415b0066e24e91a44e5f7d434cb23c";

      public static String hmac256ToHexStr(byte[] key, String msg) throws Exception {
            Mac mac = Mac.getInstance("HmacSHA256");
            SecretKeySpec secretKeySpec = new SecretKeySpec(key, mac.getAlgorithm());
            mac.init(secretKeySpec);
            return

DatatypeConverter.printHexBinary(mac.doFinal(msg.getBytes(StandardCharsets.UTF_8)))
.toLowerCase();

      }

      @PostMapping(value = "/receiveAlarmMsg")
      public ApiResult receiveAlarmMsg(@RequestBody String requestBodyStr,
HttpServletRequest request) {

            String headerSign = request.getHeader("Signature");
            String calSign;
            try {

                  calSign = hmac256ToHexStr(sk.getBytes(StandardCharsets.UTF_8),
requestBodyStr);

            } catch (Exception e) {
                  log.error("hmac256ToHexStr exception occur, e:", e);
                  // 结束方法

            }
            if (Objects.equals(headerSign, calSign)) {

                  // 签名校验通过
            } else {

                  // 签名校验不通过
            }
      }
}
```

#### 1.4.8.9 监控点报警消息抓图

```text
      监控点报警消息抓图接口为错误!未找到引用源。，使用说明参考错误!未找到引用源。。
      补充说明：

           1. 1.4.8.5 推送消息体中的 parentQrCode 或 parentMac 不为 null 时，使用推送消息体中的
                parentQrCode 或 parentMac 作为接口参数中的 qrCode、mac；

           2. 推送消息体中的 parentQrCode 和 parentMac 都为 null 时，使用推送消息体中的 qrCode
                或 mac 作为接口参数中的 qrCode、mac；

           3. 使用推送消息中的 channelId 作为抓图接口参数中的 channelId。
      使用监控点报警消息抓图的前置条件为：
      ⚫ 直连 IPC：有 SD 卡，并开启录像；
      ⚫ NVR 通道 IPC：有硬盘，且开启录像；
      ⚫ 若以上均不满足，IPC 开通云存储且开启录像上传。
      如何开启录像：
      ⚫ 设备本地开启：登录设备管理页面，进入设置-存储-录像计划，开启录像计划。
      ⚫ 在商云开启：登录商云，选择设备所在的项目，选择左侧菜单监控管理-录像设置，添加录
```
